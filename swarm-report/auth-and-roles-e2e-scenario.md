## Найденные баги

### BUG-1 (blocker, ИСПРАВЛЕН). Пустой deviceInfo ломал любой вход
- Симптом: redeem возвращал 400 `{"deviceInfo":"must not be blank"}`, клиент показывал «Код не найден».
- Причина: Koin-футган. `InviteScreenModel` создавался через `parametersOf(code)` (String-параметр),
  а `deviceInfo = get(named(...))` тоже String → Koin подставлял в `deviceInfo` инъектированный
  параметр (пустой код), игнорируя квалификатор и граф.
- Фикс: убрал строковый Koin-параметр — `prefilledCode` больше не передаётся через `parametersOf`,
  а подставляется событием `OnCodeChanged` в `LaunchedEffect`; `deviceInfo` резолвится из графа.
  Файлы: InviteScreenModel.kt, AccountFeatureModule.kt, InviteScreen.kt.
- Проверено: redeem 200, deviceInfo корректный, переход в тренерский UI.

### BUG-2 (crash, ИСПРАВЛЕН). Краш при открытии тренерского «Календаря»
- Симптом: «Trainer keeps stopping» сразу при открытии таба Календарь (воспроизводимо).
- Причина: `IllegalStateException: Vertically scrollable component measured with an infinity
  maximum height`. Двойной вложенный скролл — `DayContent` оборачивал контент в
  `Column(Modifier.fillMaxSize().verticalScroll())`, а `AppDayTimeline` внутри сам
  `Row(...).verticalScroll().height(totalHeight)`. Внешний скролл давал таймлайну бесконечную
  высоту.
- Пред-существующий: экран расписания не менялся; краш всплыл только теперь, когда календарь
  стал достижим (авторизация заработала).
- Фикс: убрал внешний `verticalScroll` в `DayContent`, таймлайн получает `Modifier.weight(1f)`
  (ограниченная высота, внутренний скролл сам работает). Файл: CoachScheduleView.kt.

### GAP-3 (blocker для go-live, НЕ исправлен — нужно решение владельца). Профиль/выход недостижимы
- `Screens.Profile` (в нём кнопка «Выйти») зарегистрирован, но на него нет ни одной навигации —
  ни в одной шапке нет входа в профиль/настройки. Пользователь не может выйти из аккаунта.
- Это пред-существующий пробел (не связан с авторизацией). Нужен перед go-live: и клиенту, и
  тренеру (у тренера медданные) нужен выход.
- Не правлю автономно: размещение входа в профиль (иконка в топ-баре рутовых экранов vs 5-й пункт
  навигации) — дизайн-решение. Экран и логика выхода готовы, нужен только вход в навигацию.

## Визуальные наблюдения
- V-1 (ИСПРАВЛЕНО): `AppTopBar` не применял top-inset статус-бара → заголовки подрезаны на всех
  авторизованных экранах. Фикс: `Modifier.statusBarsPadding()` в `AppTopBar` (Scaffolding.kt).
  Проверено: заголовок «Диалоги» с корректным отступом.
- V-2 (не исправлено, дизайн-решение): табы «Дневники» и «Люди» показывают один и тот же
  `PeopleView` с заголовком «Люди» и одинаковым пустым состоянием — отличается только действие по
  тапу. На табе «Дневники» заголовок «Люди» вводит в заблуждение. Фикс требует параметризации
  заголовка/пустого состояния `PeopleView` — оставлено на решение владельца.
- V-3 (не исправлено, нужен слой данных): в диалоге под именем собеседника подпись роли
  захардкожена «подопечный» (`DialogView`/`PEER_ROLE`). Для клиента, открывшего тренера, должно
  быть «тренер». Нужно прокинуть роль пира в состояние диалога (бэкенд `DialogResponse` → domain).
