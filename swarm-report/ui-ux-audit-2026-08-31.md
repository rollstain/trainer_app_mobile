## A. Оболочка и навигация

- [x] **A1. Переключение вкладки было холодной перезагрузкой экрана.**
  `navigator.replaceAll(rootKeyOf(tabId))` вызывал `ViewModelRegistry.clearAll()` и `stack.clear()`:
  «Сегодня» → «Люди» → «Сегодня» показывало скелетон и прокрутку с нуля.
  Пяти параллельных навигаторов не понадобилось — достаточно перестать уничтожать стек.
  Добавлен `Navigator.selectRoot(key)`: move-to-top без `clearAll()` и без `clearSubStack()`,
  корни вкладок остаются в стеке, их `SaveableStateHolder` и `ViewModelStore` живут.
  Поведение «назад» сохранено: `NavContainer` получил `isBackEnabled`, и на корне вкладки
  он `false` — системная кнопка закрывает приложение, как раньше.
  Шесть межвкладочных переходов переведены на `selectRoot`; `replaceAll` остался там, где он
  и значит «выбросить всё» — смена роли в `TelegramLinkScreen`.
  В `SeriesResultScreen` возврат к календарю сначала закрывает экраны создания серии,
  чтобы они не оставались осиротевшими в стеке.

- [x] **A2. Нижняя навигация исчезала рывком.** `AnimatedVisibility` с
  `expandVertically`/`shrinkVertically` на `screenTransitionMillis`: высота контейнера меняется
  вместе с переходом, а не в один кадр посреди анимации.

- [x] **A3. Формулировка была неточной, дефект — другой.**
  При колоночной раскладке контент не уходит под панель: она стоит ниже, и `bottom = 24` —
  это дыхание, а не компенсация инсета. Проверил заново — инсеты в порядке.
  Реальное расхождение: дыхание было только на «Сегодня» и «Дальше». На «Чатах» и «Дневниках»
  последняя строка упиралась в панель вплотную — добавлен тот же отступ 24.
  Заодно в `TodayView` убрано полное имя пакета `androidx.compose.foundation.layout.PaddingValues`,
  расписанное прямо в вёрстке.

## B. Ввод и клавиатура

- [x] **B1. `AppTextField` не задавал `imeAction` и `KeyboardActions`.** Во всём приложении не было
  ни одного `KeyboardActions`. Добавлен `TextFieldSubmit`: `None` (по умолчанию `Done` + снятие
  фокуса; для `Multiline` — перевод строки), `Next` (переход к следующему полю),
  `Done(onSubmit)` (отправка формы). Разведён по формам: вход, регистрация, восстановление,
  новый пароль, знакомство.

- [x] **B2. `KeyboardCapitalization.None` жёстко для всех видов поля.** Теперь `Sentences`
  для `Text` и `Multiline`, `None` — для почты, пароля, кода и чисел.

- [x] **B3. 15 экранов с полями не поднимались над клавиатурой.** `targetSdk = 36` — edge-to-edge
  принудительный, окно не ресайзится, `imePadding()` обязателен, а стоял только на экранах входа.
  Один `imePadding()` на колонке `AppNavigationScaffold` (`AppRoot.kt:85`) закрывает все сразу:
  каждый экран рендерится внутри неё. Чату добавлены свои `navigationBarsPadding().imePadding()`.

- [x] **B4. Дёргающийся ввод — курсор уезжал в конец.** `BasicTextField(value: String)` не хранит
  позицию курсора: любая нормализация значения в модели отбрасывала каретку.
  Било по времени (`filterTimeDigits` в рабочих часах и новом слоте), по подходам в дневнике
  (`repetitionsText = event.text.filter(Char::isDigit)`), по весу и обхватам в чек-ине.
  `AppTextField` и `AppSearchField` переведены на `TextFieldValue` с восстановлением каретки:
  `shownValueOf` сдвигает её ровно на столько символов, сколько модель добавила или убрала.

- [x] **B5. Кнопка отправки не знала про идущую отправку.** `DialogState.isSendEnabled` был
  объявлен и **не читался никем**, а `AppMessageInput` считал свой — без `isSending`/`isUploading`.
  Виджет теперь принимает флаг снаружи, дубль удалён.

- [x] **B6. Тап правее текста не попадал в поле поиска.** `BasicTextField` в `AppSearchField`
  был без `fillMaxWidth()` и занимал ширину своего текста.

## K. Приглашение подопечного

- [x] **K1. Созданный код приглашения показывался только тостом и пропадал.**
  «Люди» → «Пригласить» постил `ShowInviteCode(code)`, экран показывал тост «Код приглашения: XXXX»
  и всё — код надо было запомнить или переписать. Теперь код кладётся в буфер обмена
  и сразу открывается системное «Поделиться» (K2). Тост убран по решению владельца: он
  оказывался за системной шторкой, а шторка сама по себе — достаточное подтверждение.
  Строка `people_invite_code_copied` вместе с ним удалена из обеих локалей.
  Копирование осталось молчаливым запасным путём: отменил шторку — код всё равно в буфере.
  Копирование живёт на экране, а не в модели: буфер — забота UI. Side-effect назван по факту
  (`InviteCreated`), а не по одному из действий: `ShowInviteCode` перестал быть правдой,
  когда экран стал ещё и копировать. Именование по действию взято у донора (`CopyText`).
  Обработчику side-effect'ов передаётся операция `copyToClipboard: (String) -> Unit`, а не тип
  буфера — заодно из файла ушёл устаревший `ClipboardManager` в сигнатуре.

  **Почему устаревший API.** В Compose 1.10 новый `Clipboard.setClipEntry` из общего кода
  для текста непригоден: `ClipEntry` — `expect`-класс без общего конструктора, `withPlainText`
  есть только в uikit/macos, на Android он оборачивает `ClipData`. Рабочий из commonMain
  остаётся `ClipboardManager.setText`, помеченный deprecated.
  **Сверено с донором `urentbike-technic`** (Compose 1.9.0): там ровно тот же вызов в трёх местах
  — `CopyAddress` в `ChargingBoxSheetView`, `CopyText` в `AboutChargingBoxScreen`,
  адрес парковки в `MapParkingWithoutTasksSheetView`. То есть это домашний приём семейства,
  а не обходной путь. Заменять имеет смысл, когда в CMP появится общий способ собрать
  текстовый `ClipEntry`.
  Отличия от донора: он держит тип `ClipboardManager` в сигнатуре обработчика (и живёт
  с предупреждением) — у нас туда передаётся операция; и он копирует **молча**, без обратной
  связи, у нас тост подтверждает.

- [x] **K2. Приглашение отправляется через системное «Поделиться».** Механизм перенесён
  из донора, поверхность — нет. У донора `ShareUtils` — шесть методов (файлы, base64-картинки,
  Telegram, геолокация, сохранение в галерею) на ~40 вызовов; у нас нужен один сценарий,
